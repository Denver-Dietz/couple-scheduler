## 2024-05-24 - SQL Injection in Dynamic UPDATE Queries
**Vulnerability:** Several API endpoints dynamically construct SQL UPDATE query strings by iterating over request payload dictionary keys without verifying the keys against an explicit whitelist of allowed columns. Furthermore, f-strings were used directly inside `cursor.execute()`.
**Learning:** This codebase frequently relies on dynamic Pydantic model dumping (`payload.model_dump(exclude_unset=True).items()`) to build update queries to avoid writing boilerplate SQL. While convenient, trusting client-provided keys blindly allows an attacker to inject arbitrary column names or SQL syntax if they manipulate the JSON payload keys.
**Prevention:** Always define an explicit set of allowed columns (`allowed_columns = {"col1", "col2"}`) for the specific table being updated. Iterate over the payload and only append to the update list if the key `in allowed_columns`. Additionally, never use f-strings to format the SQL string inside `execute()`; use string concatenation or `.format()` for the query structure, and keep `?` placeholders for the values.
